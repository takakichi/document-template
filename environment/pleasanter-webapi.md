## 接続確認

プリザンターに対して、WebAPIで接続できるかどうかのサンプル。

### 1. メモ帳やVSCodeで以下の内容を test_get.json という名前で保存する（文字コードは UTF-8/BOMなし）

```json
{
  "ApiVersion": 1.1,
  "ApiKey": "ここに発行したAPIキーを貼り付け",
  "PageSize": 1,
  "View": {
    "ColumnFilterHash": {
      "Status": "[\"100\",\"200\"]"
    }
  }
}
```
- PageSize: 1: 接続確認が目的なので、最大1件だけ返すように制限しています（件数が多いテーブルでも一瞬で返ります）。
- Status: ステータスが 100（未着手）または 200（実施中）のレコードに絞り込む例です。もしレコードが0件でも、APIの認証と構文が正しければ正常応答が返ります。

### 2. curlコマンドの実行を実行する

test_get.json を保存したフォルダでコマンドプロンプト（またはPowerShell）を開き、以下を実行してください。

```DOS
curl.exe -X POST "http://サーバー名またはIP/api/items/{サイトID}/get" -H "Content-Type: application/json" -d "@test_get.json"
```
- {サイトID} は対象テーブルのURL末尾の数字（例: http://server/items/123/index なら 123）に書き換えてください。

### 3. 接続成功の判断基準

実行後、画面に以下のようなJSONが返ってくれば接続・認証・検索条件すべて正常です。

```json
{
  "StatusCode": 200,
  "Response": {
    "Offset": 0,
    "PageSize": 1,
    "TotalCount": 15,
    "Data": [ ... ]
  }
}
```
- "StatusCode": 200 が表示されていれば疎通成功です（該当データがない場合も "TotalCount": 0 で 200 が返ります）。
- 逆に 401（APIキー誤り・権限不足）、400（JSON構文エラー・サイトID誤り）、404（URLパス誤り）が返った場合は、それぞれの設定を見直してください。


## 環境設定について

**APIキーを使った外部からのAPI連携や、バックグラウンド処理（リマインダーやLDAP同期など）を利用する場合は、匿名認証を有効にした受け口が必要**になります。
IISで「Windows認証のみ有効・匿名認証は無効」にしている場合、プリザンターのアプリケーション層（APIキーの検証）に到達する手前の **IISの段階でKerberos/NTLM認証が要求され、`401 Unauthorized` で弾かれてしまう** ためです。
プリザンター公式マニュアル（統合Windows認証によるシングルサインオン）では、以下の2通りの構成が案内されています。

https://pleasanter.org/ja/manual/setup/additional/authn-authz/active-directory-sso/

---

### 1. 公式推奨：API・メンテナンス用の別サイト（別ポート）を匿名認証で立てる

ユーザーの画面ログイン用サイトは「Windows認証のみ（匿名認証無効）」のまま維持しつつ、**同じプリザンターのプログラムフォルダを参照する別サイト（例：ポート `8080` など）をIIS上に作成し、そちらだけ「匿名認証：有効／Windows認証：無効」にする**方法です。

* **ユーザー画面アクセス:** `http://{サーバー名}/` （Windows認証でSSO）
* **API実行用URL:** `http://{サーバー名}:8080/api/items/{サイトID}/get` （匿名認証で通過し、プリザンター側でAPIキー認証）

**メリット:**

* 通常のブラウザアクセス側で匿名認証を有効にしないため、統合Windows認証のSSO挙動に影響を与えません。
* API以外にも、リマインダー送信やADユーザー同期（`/users/syncbyldap`）などの定期バッチ処理も同じポート経由で実行できます。
* ファイアウォール等で `8080` 番ポートへのアクセス元を社内サーバーや管理端末のみに絞ることでセキュリティも担保できます。

---

### 2. 単一サイトのまま運用したい場合（Windows認証 ＋ 匿名認証の併用）

別ポートを立てずに既存のURLのままAPIを使いたい場合は、IISの該当サイト（または `/api` パス配下のみ）で **「Windows認証」と「匿名認証」の両方を有効** にする必要があります。

> ⚠️ **注意：同一サイトで両方を「有効」にする場合**
> プリザンターの `Authentication.json` 側で `Provider` に `Windows` が設定されていると、IISが匿名認証を通した際にWindows認証の資格情報が渡らずログイン画面にフォールバックしたり、SSOがうまく働かなくなるケースがあります。
> 既存のSSO環境を壊さないためには、**「方法1（別ポート・別サイトで匿名認証を有効化）」** で切り分けるのが最も安全で確実です。

---

### 疎通テストでの確認方法

まずは切り分けとして、IISマネージャーで **「既存のプリザンターと同じ物理パス（`Implem.Pleasanter`）を指す別サイト（例：ポート8080）」** を追加し、認証を「匿名認証：有効」に設定してみてください。
その後、`curl.exe` の宛先URLを `http://サーバー名:8080/api/items/{サイトID}/get` に変えて実行し、`"StatusCode": 200` が返ってくれば正常に連携できています。
