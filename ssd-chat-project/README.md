# ローカルLLM・チャットベース SDD PoC テンプレート

## 目的
Markdown仕様書を正本として、仕様確定→詳細設計→C#実装→試験生成→検証を、人間の承認を挟みながら進める。

## 使用方法
1. `docs/specs/requirements.md` に対象機能を記入する。
2. チャットに `docs/rules/common-rules.md`、該当工程の `docs/prompts/0X-*.md`、必要な入力成果物を順に貼る。
3. 工程1で質問に回答し、修正版仕様書を保存して人間が承認する。
4. 工程2で設計書を作り、レビュー・承認する。
5. 工程3でコードを生成・保存し、ローカルでビルドしてログを取得する。
6. 工程4で仕様から試験を生成し、ローカルで実行してログを取得する。
7. 工程5に成果物と実行ログを渡し、整合性を検証する。
8. 不適合があれば修正対象工程へ戻る。仕様変更なら必ず仕様書から更新する。

## 運用上の注意
- Ollamaのチャットにファイル読取機能がない場合は内容を手動で貼り付ける。
- 長い入力は機能・仕様ID単位で分割し、対象範囲を明記する。
- 仕様書の「承認済」は人間による承認を意味する。
- 実行ログがない場合、LLMはビルド・テスト結果を確認できない。
- 既存システムの機密情報を、許可されていない外部サービスに入力しない。

## PoC評価
仕様の曖昧さ検出、仕様IDの対応率、ビルド・試験結果、手動修正件数、仕様変更追従、別機能への再利用を記録する。
